The CS18-02-SR1 Digital I/O + Serial Module combines four digital input channels, four digital output channels, and an RS-485 serial port in a single AUX plug-in unit. This makes it well suited for installations where the Cortex PQM needs to participate in a Modbus RTU network, control external equipment such as relays or indicators, or monitor dry contact signals — all through the same expansion slot.

<Tip>
  The RS-485 serial interface can also be used to read third-party Modbus sensors and meters, aggregating their data through the Cortex PQM REST API. This lets you consolidate multiple device readings into a single interface without a separate gateway.
</Tip>

## Specifications

| Parameter | Value |
|---|---|
| Part Number | CS18-02-SR1 |
| Digital Inputs | 4 channels (dry contact) |
| Digital Outputs | 4 channels (open collector) |
| Serial Port | RS-485 half-duplex |
| Maximum Baud Rate | 115200 baud |
| Modbus RTU | Supported — slave mode, configurable address |

## Installation

<Warning>
  Power off the CSM device before connecting or disconnecting any AUX module. Inserting or removing a module with power applied may damage the device or the module.
</Warning>

<Steps>
  <Step title="Power off the CSM device">
    Remove power from the CSM device and confirm all indicator LEDs are off before handling the module.
  </Step>
  <Step title="Connect the module to the AUX port">
    Align the CS18-02-SR1 connector with the AUX port header and press firmly until fully seated.
  </Step>
  <Step title="Secure the retention clip">
    Engage the retention clip if supplied to keep the module seated under vibration.
  </Step>
  <Step title="Power on the device">
    Restore power. The module is detected automatically and its channels become available in the REST API.
  </Step>
</Steps>

## RS-485 Wiring

The RS-485 port on the CS18-02-SR1 is a half-duplex two-wire interface. Follow these guidelines to ensure reliable communication:

- Connect the **A+** and **B−** terminals of your RS-485 bus to the corresponding **A+** and **B−** terminals on the module.
- Install a **120 Ω termination resistor** across the A+ and B− terminals at each physical end of the RS-485 bus. Failure to terminate the bus correctly causes signal reflections that degrade communication at higher baud rates.
- Use shielded twisted-pair cable for the RS-485 bus. Connect the cable shield to earth ground at one end only to avoid ground loops.
- The maximum bus length is **1200 m at 9600 baud**. At higher baud rates, reduce the maximum cable length accordingly.

## Digital Output Wiring

Each digital output channel is an open-collector transistor. To use an output:

1. Connect the **output terminal** to one side of your load (relay coil, LED, indicator lamp, etc.).
2. Connect the other side of the load to a **positive supply voltage** appropriate for the load.
3. When the output is activated by the firmware, the transistor pulls the output terminal to ground, completing the circuit and energizing the load.

<Note>
  Verify that the supply voltage and load current are within the output transistor's rated limits. Refer to the CS18-02-SR1 datasheet for maximum voltage and current ratings.
</Note>

## Configuration

Set the serial port parameters in the device configuration file under the `serial` key. Choose a Modbus address that is unique on your RS-485 bus.

```json
"serial": {
  "baud_rate": 9600,
  "parity": "none",
  "stop_bits": 1,
  "modbus_address": 1
}
```

- `baud_rate` — must match the baud rate of all other devices on the RS-485 bus.
- `parity` — accepted values are `"none"`, `"even"`, and `"odd"`.
- `stop_bits` — typically `1`; set to `2` if required by your Modbus master.
- `modbus_address` — valid range is 1–247; each device on the bus must have a unique address.

Configure digital input and output channels in the same configuration file under the `digital_inputs` and `digital_outputs` arrays:

```json
"digital_inputs": [
  { "id": 1, "name": "Door Interlock", "mode": "status" },
  { "id": 2, "name": "Run Feedback", "mode": "status" }
],
"digital_outputs": [
  { "id": 1, "name": "Alarm Relay", "active_high": true },
  { "id": 2, "name": "Indicator Light", "active_high": true }
]
```

- `mode` — for inputs, `"status"` reports the current open/closed state; `"pulse_count"` accumulates a rising-edge counter.
- `active_high` — when `true`, setting the output to `on` pulls the open-collector output high (via external load); when `false`, the logic is inverted.

## Data Access

Once the CS18-02-SR1 is installed and configured, you can read digital input states and control digital outputs through the Cortex PQM REST API.

**Read digital input states:**

```http
GET http://{device-ip}/api/digital_inputs
```

Example response:

```json
{
  "digital_inputs": [
    { "id": 1, "name": "Door Interlock", "state": "closed", "mode": "status" },
    { "id": 2, "name": "Run Feedback", "state": "open", "mode": "status" }
  ]
}
```

**Set a digital output state:**

```http
POST http://{device-ip}/api/digital_outputs/1
Content-Type: application/json

{ "state": "on" }
```

**Read current output states:**

```http
GET http://{device-ip}/api/digital_outputs
```

Example response:

```json
{
  "digital_outputs": [
    { "id": 1, "name": "Alarm Relay", "state": "on" },
    { "id": 2, "name": "Indicator Light", "state": "off" }
  ]
}
```

<Note>
  Output states are not retained across a power cycle by default. If you need outputs to return to a known state on startup, set the `default_state` field for each output channel in the configuration file.
</Note>
