The Cortex PQM CSM-1-00 and CSM-2-00 provide a REST API for reading meter data and writing configuration over HTTP. Responses are JSON.

<Warning>
  Endpoints, field names, data types, and response formats may be added, changed, or removed in firmware releases. API changes are documented in the release notes accompanying each firmware update. If you maintain an integration (SCADA, BMS, energy platform, dashboard, reporting tool), test it after every firmware update. The installed firmware version is available from `/api/deviceinfo` (`firmwareMajor`, `firmwareMinor`, `firmwareRevision`) and on the **System** page of the web console.
</Warning>

## Base URL

All requests are made to the meter's IP address. **No authentication is required.**

```text
http://<device-ip>/api/<endpoint>
```

The default IP address is `192.168.7.3`. To test the connection, open `http://192.168.7.3/api/healthcheck`; a response with `"data": 1` confirms the monitor is reachable.

## Standard Response Envelope

All GET responses share this structure:

```json
{
  "endpoint": "/api/kw",
  "url": "http://192.168.7.3/api/kw",
  "data": { ... }
}
```

All readable endpoints use `GET`, need no request body, and return JSON.

## Circuit Range Parameters

Per-circuit endpoints accept `?id=N` (single circuit) or `?start=N&end=M` (range). Default: all 192 circuits.

```bash
curl "http://192.168.7.3/api/kw?start=1&end=4"
```

## Status & System

### GET /api/healthcheck

Returns `1` if the device is alive. Any other response or a connection failure indicates the device is unreachable or rebooting.

```json
{ "endpoint": "/api/healthcheck", "url": "http://<device-ip>/api/healthcheck", "data": 1 }
```

### GET /api/version

```json
{ "data": { "major": 1, "minor": 0, "revision": 1, "buildNumber": 0 } }
```

### GET /api/deviceinfo

Hardware identification, connected card topology for all Flex Ports and the AUX (digital) port, per-card firmware versions, and the device RTC time. Field names follow the pattern `flexPortDeviceType_<port>_<card>`.

```json
{
  "data": {
    "serialNumber": 54908,
    "macAddress": "BC:DF:E1:80:27:97",
    "modelName": "CSM-1-00",
    "deviceName": "Office Panel A",
    "firmwareMajor": 1, "firmwareMinor": 0, "firmwareRevision": 1,
    "uptime": 18426,
    "flexPortStatus_1": 0, "flexPortDevices_1": 2,
    "flexPortDeviceStatus_1_1": 0, "flexPortDeviceType_1_1": 3, "flexPortFwVersion_1_1": 262,
    "digitalPortStatus": 0, "digitalPortDevices": 3,
    "digitalPortDeviceStatus_1": 0, "digitalPortDeviceType_1": 5, "digitalPortFwVersion_1": 258,
    "rtctime": "April 20, 2026 04:30:21 PM"
  }
}
```

- `uptime` is in seconds since last boot.
- Serial `4294967295` (0xFFFFFFFF) = card reports no serial.
- Device status codes: 0 = normal.

| Device type code | Device |
| --- | --- |
| 3 | CT Strip |
| 5 | Digital Input Board |
| 10 | CT Strip type B |
| 21 | Thermal Input Board |
| 22 | Digital I/O Board |
| 23 | MULTI_CARD_12CT |
| 25 | BUSWAY_6CT |

### GET /api/systemstatus

Per-thread CPU utilization (%), per-thread stack usage (%), filesystem storage statistics, and microcontroller identifiers. Thread 9 is the metering/DSP thread and normally shows the highest CPU usage (~30%).

### GET /api/usbstatus

```json
{ "data": { "usbConnected": true, "configFile": "Cortexsettings.json", "updateFile": "" } }
```

### GET /api/modbustcpstatus

Modbus TCP socket states. Socket 0 is always the listener on port 502. Up to 15 concurrent Modbus TCP clients are supported. Socket states: `LISTEN` (waiting), `CLOSED` (idle), `ESTABLISHED` (active session).

### GET /api/waveforminfo and /api/waveformstatus

`/api/waveforminfo` lists captured AC waveform CSV files (up to 5 are stored; the oldest is overwritten). Trigger a capture with `POST /configSettings` and `"startWaveformCapture": true`, then poll `/api/waveformstatus` until `waveformCaptureInProgress` is `false`.

### GET /api/csr

Returns the device's TLS Certificate Signing Request as raw PEM text (`application/x-pem-file`, no JSON wrapper). To enable HTTPS:

1. Obtain the CSR and submit it to your certificate authority.
2. Upload the signed certificate via `POST /fileupload` (`.pem` or `.crt`, up to 1 MB).
3. Post `{ "deviceConfig": { "httpsEnable": true } }` to `/configSettings`.
4. Restart the device.

## Power & Energy

All nine Power & Energy endpoints share the same response shape; only `dataType` and the values differ.

```json
GET /api/kw?start=1&end=4
{
  "data": {
    "dataType": "kw",
    "readings": {
      "circuit_1": 0.0258,
      "circuit_2": 0.0131,
      "circuit_3": 0.0259,
      "circuit_4": 0.0132
    }
  }
}
```

| Endpoint | Unit | Description |
| --- | --- | --- |
| `/api/kw` | kW | Real (active) power |
| `/api/kwh` | kWh | Cumulative real energy. Not reset on restart |
| `/api/kvar` | kVAR | Reactive power |
| `/api/kvarh` | kVARh | Cumulative reactive energy |
| `/api/kva` | kVA | Apparent power |
| `/api/kvah` | kVAh | Cumulative apparent energy |
| `/api/current` | A (RMS) | RMS current |
| `/api/kwdemand` | kW | Real power demand over the configured demand interval |
| `/api/currentdemand` | A | Current demand over the configured demand interval |

## Power Quality

| Endpoint | Unit | Description |
| --- | --- | --- |
| `/api/pf` | ratio 0–1 | Power factor (leading/lagging not differentiated) |
| `/api/phaseangle` | degrees | Phase angle between voltage and current |
| `/api/thdi` | % | Current THD as % of the fundamental. Values over 100% are normal for SMPS loads. Circuits with no CT return 0 |
| `/api/crestfactor` | ratio | Peak / RMS current. Pure sine = 1.414 |

## Harmonic Analysis

- **`/api/harmonicsi`** — per circuit: `percentTHD` and a `harmonics` array of up to 21 values (% of fundamental). Index 0 = 3rd harmonic, up to the 23rd.
- **`/api/harmonicsv`** — for `input_1` and `input_2`, per phase (L1/L2/L3): `percentTHD_LN`, `percentTHD_LL`, and a `harmonics` array of up to 63 values. Index 0 = 2nd harmonic. `percentTHD_LL` is computed only for L1 (the L12 reference phase).

## Voltage & Frequency

`/api/volts` returns both voltage inputs; `/api/volts1` and `/api/volts2` return one. Readings include line-to-neutral and line-to-line voltages, per-phase THD, phase angles, frequency, and a decoded alarm status object.

```json
GET /api/volts1
{
  "data": {
    "dataType": "volts",
    "readings": {
      "voltage_L1": 121.634, "voltage_L2": 61.178, "voltage_L3": 61.271,
      "voltageLN_Avg": 81.361,
      "voltage_L12": 60.839, "voltage_L23": 0, "voltage_L31": 60.957,
      "voltageLL_Avg": 40.599,
      "thd_L1": 2.652, "thd_L2": 3.308, "thd_L3": 3.305,
      "phaseAngle_L1": 0, "phaseAngle_L2": 1.215, "phaseAngle_L3": 1.121,
      "frequency": 60.003
    },
    "status": {
      "voltage_L12": 514,
      "voltage_L12_Alarms": { "overVoltageLatchingAlarm": false, "underVoltageLatchingAlarm": true, "...": "..." }
    }
  }
}
```

**Voltage alarm bitmask (16-bit):** bit 0 over voltage latching, bit 1 under voltage latching, bit 2 frequency deviation latching, bits 3–7 reserved, bit 8 over voltage non-latching, bit 9 under voltage non-latching, bit 10 frequency deviation non-latching, bit 11 phase rotation non-latching, bits 12–15 reserved. Example: `514` = bits 1 and 9. Clear latched alarms with `POST /configSettings` and `"clearVoltageAlarmLatches": true`.

## Safety & Monitoring

### GET /api/alarms

Current alarm bitmask per circuit (non-zero = alarm active).

| Bit | Field | Description |
| --- | --- | --- |
| 0 | `highLatchingAlarm` | High current latching alarm |
| 1 | `highLatchingWarning` | High current latching warning |
| 2 | `lowLatchingAlarm` | Low current latching alarm |
| 3–5 | – | Reserved |
| 6 | `currentDropLatchingAlarm` | Current drop latching alarm |
| 7 | `vpLatchingAlarm` | Voltage presence latching alarm |
| 8 | `highNonLatchingAlarm` | High current non-latching alarm |
| 9 | `highNonLatchingWarning` | High current non-latching warning |
| 10 | `lowNonLatchingAlarm` | Low current non-latching alarm |
| 11–13 | – | Reserved |
| 14 | `currentDropNonLatchingAlarm` | Current drop non-latching alarm |
| 15 | `vpNonLatchingAlarm` | Voltage presence non-latching alarm |

Latching alarms persist until cleared with `POST /configSettings` and `"clearCircuitAlarmLatches": true`. Thresholds are configured in `/api/devicesettings` under `alarm.current`.

### GET /api/breakerutilization

Breaker utilization per circuit, `(current ÷ breakerSize) × 100`, in percent (1.18 = 1.18%).

## Circuit Configuration (Read + Write)

These endpoints return per-circuit configuration via GET and accept writes via `POST /configSettings`. Send only the circuits you want to change; omitted circuits are left unchanged.

| GET endpoint | POST key | Values | Description |
| --- | --- | --- | --- |
| `/api/circuitname` | `circuitName` | string | Display name |
| `/api/ctsize` | `ctSize` | amps | CT rated size |
| `/api/breakersize` | `breakerSize` | amps | Breaker rating (0 = not configured) |
| `/api/voltagephase` | `voltagePhase` | 0, 1, 2 | 0 = L1, 1 = L2, 2 = L3 |
| `/api/cttype` | `ctType` | integer | CT type code |
| `/api/flexmeterassignment` | `flexMeterAssignment` | 0–96 | Flex Meter group (max 3 circuits per meter) |
| `/api/aggregatemeterassignment` | `aggregateMeterAssignment` | 0–8 | Aggregate Meter group |

```json
POST /configSettings
Content-Type: application/json
{
  "circuitName":         { "circuit_1": "Panel A Breaker 1" },
  "ctSize":              { "circuit_1": 100 },
  "breakerSize":         { "circuit_1": 20 },
  "voltagePhase":        { "circuit_1": 0 },
  "flexMeterAssignment": { "circuit_1": 3 }
}
```

Success response: `{ "status": "ok" }`

### GET /api/devicesettings

The complete device configuration: `deviceConfig`, `ipv4`, `ipv6`, `modbus`, `alarm`, `voltage`, `demand`, `phaseSettings`, and `panel_1`–`panel_4`. Writable via `POST /configSettings`. See [Configuration File Definitions](/configuration/file-definitions).

- Alarm thresholds in `alarm.current` are in tenths of a percent (800 = 80.0% of breaker rating).
- IP and Modbus changes, and the security toggles (`httpsEnable`, `modbusTCPEnable`, `modbusTLSEnable`), require a restart. Alarm thresholds and names take effect immediately.

```json
POST /configSettings
{ "deviceConfig": { "deviceName": "Panel A - Row 1" }, "modbus": { "slaveId": 5 } }
```

### GET /api/downloadsettings

Same body as `/api/devicesettings`, served with `Content-Disposition: attachment` for saving a configuration backup. Restore a backup with `POST /fileupload`.

## Meter Grouping

- **`/api/flexmeter`** — per-circuit readings (kW, kVA, kVAR, kWh, current, PF, THD, crest factor, utilization, peaks) for up to 3 circuits per Flex Meter, plus a `total` object with voltage and neutral current. Use `?id=N` for one meter.
- **`/api/flexmetername`** — names for all 96 Flex Meters (default "Flex Meter #N"). Write with key `flexMeterName`.
- **`/api/aggregatemeter`** — per-line (L1/L2/L3) and total readings for all 8 Aggregate Meters. `percentUtilization` is a fraction; multiply by 100 for display.
- **`/api/aggregatemetername`** and **`/api/aggregatemeterbreakersize`** — writable with keys `aggregateMeterName` and `aggregateMeterBreakerSize`.

<Note>
  Some firmware field names contain typos that integrations must match exactly, for example `maxInstantanrousCurrent` (Flex Meter `total`) and `numberOfCircuitsAssgined` (Aggregate Meter `line_N`).
</Note>

## Expansion Devices

### GET /api/multicarddata

Status and readings from Multi-Cards (MULTI_CARD_12CT) on the Flex Ports: `diValue` and `doValue` bitmasks and up to 5 RTD readings per card (`999.99` = not connected or out of range).

### GET /api/auxport

All cards on the AUX port in a single `auxCards` array. Replaces the retired `/api/digitalinputs` and `/api/thermalinputs` routes.

| Card type | Description |
| --- | --- |
| `di` | Digital Input Board (18 DI channels) |
| `dio` | Digital I/O Board (18 DI channels + 2 relay outputs) |
| `thermal` | Thermal Input Board (18 RTD sensor slots + board temperature on channel 19) |

- DI/DO values: 1 = closed / energized, 0 = open.
- DI channels are numbered sequentially across cards (card 1 = 1–18, card 2 = 19–36, …); DIO DO channels use card-local numbering (1 and 2).
- Thermal values are in °C; `999.99` = not connected or out of range.
- Writable via `POST /configSettings`: `diName.channel_N`, `doName.channel_N`, `rtdName.channel_N`, and `doData.output_N` (0 or 1, N = global DO channel number).

## File Downloads

### GET /waveform/\<filename>

```bash
curl http://<device-ip>/waveform/waveform_20260418_143022.csv -o waveform.csv
```

Time-series voltage and current samples captured at 2,560 Hz.

### GET /log/\<filename>

```bash
curl http://<device-ip>/log/itic_log.csv -o itic_log.csv
```

`itic_log.csv` contains timestamped CBEMA/ITIC power quality events (voltage sags and swells) with duration (ms), voltage magnitude (% of nominal), and classification.

<Warning>
  Clearing the ITIC log with `POST /configSettings` and `"clearITICEvents": true` is irreversible.
</Warning>
