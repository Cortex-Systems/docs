This page documents what changed in each firmware release for the Cortex PQM (CSM-1-00 / CSM-2-00), including new features, bug fixes, and any breaking changes that may require configuration migration. Review the relevant release notes before applying an update to understand how the new version may affect your installation.

<Note>
  For the latest firmware files, contact Cortex Systems support or visit the [Cortex Systems support portal](https://support.cortexsystems.com). Firmware downloads include an official release notes document with accurate version numbers, release dates, and detailed migration instructions.
</Note>

## Release History

<AccordionGroup>
  <Accordion title="v1.3.0">
    **New Features**
    - Added three-phase power factor measurement, available via the web interface and REST API (`GET /api/power-factor`)
    - Extended Modbus register map to expose per-phase power factor values

    **Improvements**
    - Improved Modbus response time under high polling rates
    - Reduced memory usage during sustained high-frequency logging

    **Bug Fixes**
    - Fixed an edge case where power factor calculations returned incorrect values when load was near zero
  </Accordion>

  <Accordion title="v1.2.0">
    **New Features**
    - Added REST API endpoint for per-circuit energy totals: `GET /api/circuits/{id}/energy`
    - Added configurable energy accumulation reset via API: `POST /api/circuits/{id}/energy/reset`

    **Bug Fixes**
    - Fixed CT ratio rounding bug that caused minor inaccuracy in energy calculations when using non-standard CT ratios
    - Fixed an issue where the web interface displayed stale values after a configuration change without requiring a manual page refresh
  </Accordion>

  <Accordion title="v1.1.0">
    **New Features**
    - Added support for the CS18-01-TMP thermal expansion module
    - Temperature readings from CS18-01-TMP are accessible via `GET /api/temperature`

    **Improvements**
    - Improved DHCP reliability on networks with slow lease response times
    - Improved device recovery behavior when network connectivity is briefly interrupted

    **Bug Fixes**
    - Fixed a startup delay that occurred on networks without a DNS server configured
  </Accordion>

  <Accordion title="v1.0.0">
    **Initial Release**

    - First production firmware for CSM-1-00 and CSM-2-00
    - Core power quality monitoring: voltage, current, real/reactive/apparent power, frequency, and THD
    - Modbus TCP and RTU support
    - REST API for data access and device configuration
    - Web interface for configuration, monitoring, and diagnostics
    - USB firmware update support
    - OTA firmware update via web interface and REST API
  </Accordion>
</AccordionGroup>

<Note>
  Version numbers and dates above are illustrative examples. Refer to the official release notes document included with your firmware download for the complete and accurate version history applicable to your device.
</Note>

<Tip>
  Always read the release notes before updating. Some versions include configuration migration steps — for example, changes to register maps or API endpoints that require updates to your integration before you apply the firmware.
</Tip>
