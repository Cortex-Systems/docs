The over-the-air (OTA) update method pushes firmware to your Cortex PQM (CSM-1-00 / CSM-2-00) over an Ethernet connection — no physical access to the device is required. You can trigger an OTA update through the web interface for a guided experience, or via the REST API for scripted and automated deployments across multiple devices.

## Prerequisites

- The device is connected to your network via Ethernet
- You have the firmware `.bin` file available on your local machine or accessible at a URL
- You can reach the device's IP address from the machine initiating the update

## Method 1: Web Interface

Use the web interface when you prefer a guided, point-and-click experience.

<Steps>
  <Step title="Open the device web interface">
    In a browser, navigate to the device's IP address (for example, `http://192.168.1.100`).
  </Step>

  <Step title="Navigate to the firmware update page">
    Go to **Settings → Firmware Update**.
  </Step>

  <Step title="Select the firmware file">
    Click **Choose File** and select the firmware `.bin` file from your local machine.
  </Step>

  <Step title="Start the update">
    Click **Upload and Update** to begin the process. A progress indicator will appear.
  </Step>

  <Step title="Wait for the update to complete">
    The update takes approximately **3 minutes**. Do not close the browser tab or navigate away during this time, as doing so may interrupt the process.
  </Step>

  <Step title="Confirm the new firmware version">
    The device reboots automatically when the update is complete. Once it reconnects, go to **Settings → About** to verify the firmware version reflects the update.
  </Step>
</Steps>

## Method 2: REST API

Use the REST API to update firmware programmatically — for example, in a deployment script or when updating multiple devices without opening a browser.

<Steps>
  <Step title="POST the firmware file to the device">
    Send the firmware `.bin` file to the device using a `POST` request. Replace `192.168.1.100` with your device's IP address.

    ```bash
    curl -X POST http://192.168.1.100/api/firmware \
      -H "Content-Type: application/octet-stream" \
      --data-binary @cortex_firmware.bin
    ```

    A `200 OK` response confirms the file was accepted and the update has started.
  </Step>

  <Step title="Poll the update status">
    Monitor the update progress by polling the status endpoint:

    ```bash
    curl http://192.168.1.100/api/firmware/status
    ```
  </Step>

  <Step title="Wait for the completion response">
    Continue polling until you receive a `complete` status:

    ```json
    { "status": "complete", "version": "x.x.x" }
    ```

    This indicates the update finished successfully. The `version` field reflects the newly installed firmware version.
  </Step>

  <Step title="Allow the device to reboot">
    The device reboots automatically after a successful update. Wait for it to come back online before resuming normal API communication.
  </Step>
</Steps>

<Warning>
  Do not make other API calls or modify device configuration while a firmware update is in progress. Concurrent requests during the update may cause unpredictable behavior.
</Warning>

<Note>
  If the update fails, the status endpoint returns `{"status": "error"}`. In this case, the device retains the previously installed firmware version and continues operating normally. Check that the `.bin` file is valid and compatible with your device model, then retry the update.
</Note>
